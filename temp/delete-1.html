Destructive Actions

A three-tier system for destructive actions, scaled to the risk level of each operation.

Tier 1 — Secondary Destructive
Secondary destructive action. Used alongside a primary save/confirm action. The delete button is anchored to the left in a split footer layout, visually separated from the primary action on the right. Button labels use sentence case to keep tone calm and deliberate.

Tier 2 — Tertiary Destructive
Tertiary destructive action embedded in a context menu or inline list. A generous separator above the delete item creates visual distance from safe actions, reducing misclick risk. The label names the specific resource being deleted rather than using a generic "Delete" to eliminate ambiguity.
Tier 3a — Primary Destructive
Confirmation modal for deleting items with no active dependents. Permanence is communicated through a dedicated warning block rather than buried in body copy. An explicit close button and Escape key support provide clear exit paths without requiring the user to hunt for a cancel action.

Tier 3b — Primary Destructive, High-Stakes
High-stakes delete for items with active dependents or shared impact. The user must type the exact resource name before the delete action enables. Inline validation confirms the match in real time, and a case-sensitive hint prevents silent errors from minor typos.

Tier Style Use when Examples
